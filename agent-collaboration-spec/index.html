規格 · 不綁工具 · 不含實作細節

檔案當記憶，對話用完就丟

長時間的 agent 工作裡，你不讀回覆，只讀狀態和證據。這份規格只說要守住哪些規則；怎麼實作，由實作者決定。

所有角色只透過檔案層溝通

回覆是事件流，你要的是現況

長任務裡，背景工作每完成一次，就叫醒主線回一段。每一段單看都合理，疊起來就出現五個症狀，分成兩類。

讀者端：你讀得很累

  • 重複的資訊
  • 重點被埋在某個角落，要全部讀完才敢確定沒漏
  • 前後矛盾

Context 端：agent 變笨、變貴

  • 雜訊引發幻覺
  • 浪費 context 與 token

兩類都要從根本解決。只讓畫面安靜、context 照樣被佔的做法不算數。

七條規則

P1 檔案當記憶

計畫、進度、決策、結果、證據都寫進檔案，跟專案一起保存。沒寫進檔案的事，對接手的 agent 等於不存在。

P2 對話用完就丟

任何角色只靠檔案就能接手。階段之間換乾淨的 context：只帶上一階段的產出進場，不帶對話紀錄。

P3 只傳參照，不傳全文

角色之間不靠長訊息傳話。Worker 把產出存進檔案層，回給主線的只有一句結論和去哪裡看。不失真，也省 token。

P4 寫入單線

同一批檔案，同一時間只有一個寫入者。其他角色貢獻判斷，不動手改。共用的狀態也只有一個角色能寫。

P5 狀態和日誌分開寫

兩者都要。狀態回答「現在是什麼情況」，給你讀。日誌回答「發生過什麼」，給接手的 agent 和追查時用。

P6 用驗證取代閱讀

你不讀過程，也不逐行讀產出，只檢查驗證產物：影片、截圖、圖表、測試與形式化驗證的輸出。負責驗證的角色沒看過製作過程。

P7 主線保持短

長任務不放在主線跑，交給背景 session 或 workflow。主線只調度：不讀全文，不自己維護狀態。

每個症狀由哪些規則處理

症狀處理它的規則
重複的資訊P5 狀態只留現況；彙整時去重
重點被埋狀態分成四組；簡報先講結論；要你決策的事主動通知
前後矛盾P4 共用狀態只有一個寫入者；寫簡報的角色沒看過過程
雜訊引發幻覺P2、P3、P7：雜訊不進主線，階段之間不帶對話
浪費 context 與 tokenP3 只傳參照；P7 主線保持短

六個角色，各管一件事

角色做什麼不做什麼
主線拆任務、派工、收參照不讀全文、不跑長任務、不維護狀態
Worker做一件事。收尾時寫下自己的結果，回一句參照後結束不改別人負責的檔案、不寫共用狀態
彙整者把各 worker 的結果彙整成共用狀態，去重、消除矛盾不做任務本身
驗證者只拿需求和產出，實際驗證並留下證據不看製作過程、不修改產出
簡報者你回來時，只依狀態和證據寫一份簡報不看製作過程、不加自己的推測
你在檢查點讀狀態與證據、做決策不讀過程對話

角色是職責，不是固定的 agent 數量。一個職責可以由多個 agent 分擔，但同一個 agent 不同時負責「做」和「驗」。

檔案層放五種東西

種類回答的問題誰寫主要讀者
計畫要做什麼、怎樣算完成主線所有角色
狀態現在是什麼情況彙整者你、主線、簡報者
日誌發生過什麼、做過哪些決定各角色，只追加自己的接手的 agent、追查時的你
結果這件工作的產出負責那件工作的 worker驗證者、彙整者
證據憑什麼相信產出是對的驗證者你、簡報者

狀態會被改寫，永遠只留現況。日誌只追加，不回頭改。兩者不放在同一處。

平時看四組狀態，回來時讀一份簡報

每件工作落在四組之一

  • 需要你決策卡住了，你不決定就不會往下走。主動通知你，不排隊等你回來。
  • 需要你注意沒有卡住，但出現風險或異常，你應該知道。
  • 還剩下正在做，或排著還沒做。
  • 已完成做完，而且附上證據。沒有證據不算完成。

簡報的三個要求

  • 先結論，再細節。
  • 每一點都指得回證據。
  • 同一件事只出現一次，前後不矛盾。

會改到同一批檔案的工作，預設不拆

Agent 自己按任務拆分、自己開 session，不需要你逐一派工。拆之前先問一個問題：這兩件工作會改到同一批檔案嗎？

不會

平行

各開各的 session，各寫各的檔案。

會 · 預設

依序

交給同一個寫入者，一件做完再做下一件。

會 · 例外

隔離後平行

各自在隔離的工作副本裡做（例如 git worktree），並指定單一整合者負責合併。

!

隔離擋不住隱性決定。工作副本擋得住檔案互蓋，擋不住兩邊各自對風格、邊界情況、慣例做的決定，合併時仍會衝突。所以平行寫入只當例外。

同時進行的數量不設上限。出現你檢查不過來、或品質下降的情況時，再加上限。

你只在固定檢查點介入

  • 檢查點研究完成後
  • 檢查點重大設計決定前
  • 檢查點交接時
  • 檢查點發佈前
  • 任何時候出現需要你決策的事，主動通知你

檢查點之間，agent 自己往下做，不需要你盯著。上面四個時點是起點，確切位置和數量可以調整。

工具還沒補上的缺口，用繞的

以 Claude Code 為例：在單一 session 裡，背景通知會逐一觸發主線回覆。撰寫這份規格時，沒有找到能合併或延後這些通知的設定。

規格的做法是繞過它，也就是 P7：長任務交給背景 session 或 workflow，主線不會被反覆叫醒。

!

靜音只是補丁。要求主線不回話、或把畫面上的文字換掉，畫面會安靜，context 照樣被佔。可以當過渡，不能當解法。

這份規格不決定的事

下面這些留給實作者設計：

  • 檔案的格式、欄位和目錄結構
  • 各角色的提示詞
  • 用哪個工具的哪個功能來開 session、隔離工作副本、發通知
  • 四組狀態用什麼畫面呈現
  • 檢查點的確切位置和數量

實作可以自由選擇，只要七條規則，以及每個角色「不做什麼」那一欄都守住。
